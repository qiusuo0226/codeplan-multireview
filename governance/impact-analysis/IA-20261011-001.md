# Impact Analysis

## CR ID

CR-20261011-001

## Summary

0.5.2 把开发仓的升级核对收成九节编号清单。同一会话里没有执行该版的另一个助手来写。执行者不写进度。预期、范围、不改项写进 CR，回归和结果写进 RR，删方案之后仍可抄。版本、打包、发布记录的条目写在核对模板里。分发的业务技能行为不变。

## Affected Layers

| Layer | Affected | Notes |
|---|---|---|
| Contract (`SKILL.md` / `skill.json`) | yes | `SKILL.md` 不改。`skill.json` 只改 `version` 和 `versionHistory`。description 不改 |
| Rules (`references/`) | no | `references/` 不改。改的是 `governance/rules/`，不进分发包 |
| Templates (`assets/`) | no | 改的是 `governance/templates/`，不进分发包 |
| Scripts (`scripts/`) | no | |
| Tests (`tests/`) | yes | 新增 `test_upgrade_effect_contract.py`。既有契约测试和变异测试不改 |
| Pack / version scripts | yes | `VERSION` 与 `sync_version.py`。脚本本身不改。核对模板不进 zip |

## Affected Capabilities

| Capability | Impact | Risk | Need Regression |
|---|---|---|---|
| 开发仓升级核对 | high | 口令、谁来写、对人正文都变 | yes |
| 业务方案的 Agent B | none | 五句触发、十节、硬闸 1 至 15 不改 | yes |
| 问人数与执行闸 | none | 0.5.1 的句子不改 | yes |
| 缺口捕捉 | none | `gap-capture.md` 不改 | yes |
| 已发出的方案 | none | 不改文件，不要求补写栏目 | yes |

## Compatibility

- [ ] 不影响已安装的旧版使用者
- [x] 需要使用者重装 Skill
- [ ] 需要工作区迁移（默认无）

不需要工作区迁移。已发出的业务方案不改。核对规则在 `governance/`，分发包不含这部分。已安装的副本要覆盖安装后，安装目录里的核对口令才按九节清单回复。业务技能的触发短语、十节名称和硬闸不变，只换 zip 时业务行为与 0.5.1 相同。

## Rollback Plan

1. 回到基线 `governance/baselines/0.5.1/`
2. `VERSION` 改回 `0.5.1`，重跑 `governance/scripts/sync_version.py`
3. 不在失败版本上打补丁。基线一旦生成 `0.5.2/` 就不改、不删。不推远程
