# Impact Analysis

## CR ID

CR-20261010-002

## Summary

0.5.1 让指定方案里已经写上的真实轮次就是审核。决定改代码前必须读完格式样例之后的每一节，只用最后一节判断。该节可以执行且对照修订等于当前 revision 时，不再另要审核人数。骨架里没有覆盖五格的已有一轮不因此无效。十节名称和五句触发短语不变。

## Affected Layers

| Layer | Affected | Notes |
|---|---|---|
| Contract (`SKILL.md` / `skill.json`) | yes | 硬闸 2、5、15 的适用范围、身份段、description、版本 |
| Rules (`references/`) | yes | 只改 `01-plan-review.md`。`gap-capture.md` 不改 |
| Templates (`assets/`) | no | |
| Scripts (`scripts/`) | no | |
| Tests (`tests/`) | yes | 契约测试加新原句，并断言旧整句不在 |
| Pack / version scripts | yes | `VERSION` 与 `sync_version.py`。脚本本身不改 |

## Affected Capabilities

| Capability | Impact | Risk | Need Regression |
|---|---|---|---|
| 问人数 | high | 已有真实轮次或文首已写 reviewers 时不再问。还没有方案文件时仍问 | yes |
| 写代码 | high | 先读完每一节。最后一节对得上当前 revision 且可以执行，人拍板后才改 | yes |
| 审核格式 | medium | 新一轮仍要五格。骨架没有 `### 覆盖` 的已有一轮不追溯判无效 | yes |
| 触发与十节 | none | 五句触发和十节名称不改 | yes |
| 缺口捕捉 | none | `gap-capture.md` 不改 | yes |
| 已发出的方案 | low | 不改文件，不要求补写五格 | yes |

## Compatibility

- [ ] 不影响已安装的旧版使用者
- [x] 需要使用者重装 Skill
- [ ] 需要工作区迁移（默认无）

不需要工作区迁移。已有 `outputs/codeplan/` 不用改、不删。已发出方案的「交给审核」不会自动更新。新骨架只进入以后新写的方案。

## Rollback Plan

1. 回到基线 `governance/baselines/0.5.0/`
2. `VERSION` 改回 `0.5.0`，重跑 `governance/scripts/sync_version.py`
3. 不删除已生成的业务方案目录。基线一旦生成 `0.5.1/` 就不改、不删
