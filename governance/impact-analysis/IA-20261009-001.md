# Impact Analysis

## CR ID

CR-20261009-001

## Summary

0.4.0 要求业务方案把回归验证和 bug修复验证写进验收，执行里的代码一行一中文注释，改完代码后按验收逐条验证。十节名称、触发短语和人数规则不变。

## Affected Layers

| Layer | Affected | Notes |
|---|---|---|
| Contract (`SKILL.md` / `skill.json`) | yes | 新硬闸 13、版本。description 不改 |
| Rules (`references/`) | yes | 只改 `01-plan-review.md`。`gap-capture.md` 不改 |
| Templates (`assets/`) | no | |
| Scripts (`scripts/`) | no | |
| Tests (`tests/`) | yes | 契约测试加原句 |
| Pack / version scripts | yes | `VERSION` 与 `sync_version.py`。脚本本身不改 |

## Affected Capabilities

| Capability | Impact | Risk | Need Regression |
|---|---|---|---|
| 写方案 | high | 验收两节和逐行注释，缺了不能交 B | yes |
| 审核 | high | 未安装技能的 B 只看新骨架 | yes |
| 写代码 | high | 改完必须按验收验证 | yes |
| 人数与触发 | none | 硬闸 2 和五句触发保留 | yes |
| 缺口捕捉 | none | `gap-capture.md` 不改 | yes |
| 已发出的方案 | low | 旧「交给审核」不自动改写 | yes |

## Compatibility

- [ ] 不影响已安装的旧版使用者
- [x] 需要使用者重装 Skill
- [ ] 需要工作区迁移（默认无）

不需要工作区迁移。已有 `outputs/codeplan/` 不用改、不删。已发出方案的「交给审核」不会自动更新。要让旧方案上的 B 看见新句子，由 A 原样重抄第 10 节，revision 不加。

## Rollback Plan

1. 回到基线 `governance/baselines/0.3.1/`
2. `VERSION` 改回 `0.3.1`，重跑 `governance/scripts/sync_version.py`
3. 不删除已生成的业务方案目录。基线一旦生成 `0.4.0/` 就不改、不删
