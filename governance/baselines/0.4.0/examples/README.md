# 使用示例

看怎么开口、助手问什么、你怎么回、文件夹里会多出什么。

人名、仓库和问题是假的，问法是真的。01 到 07 贯穿同一件事：林夏的 `local-notes` 退出登录后，草稿还留在浏览器里。08 是另一份已经走完多轮审核的完整方案，路径和账号已换成 `local`。

```mermaid
flowchart LR
    A["说出问题"] --> B["同意出方案，并说出几名 B"]
    B --> C["A 写下 a-body.md"]
    C --> D["每名 B 另开对话"]
    D --> E["最新一轮都是可以执行"]
    E --> F["你说开始按方案执行"]
```

建议先看 01。人数没说清看 02。方案正文看 03。审核看 04。两名以上看 05。改代码看 06。技能本身做不到看 07。要看一份长方案看 08。

## 开口

| 文件 | 看什么 | 你开口可以这样说 |
|---|---|---|
| [01-先问再出方案.md](01-先问再出方案.md) | 扫完要改代码，先问，不写方案 | 描述问题 |
| [02-人数由你指定.md](02-人数由你指定.md) | 没说人数就只问，不自己定成两名 | 「出一版升级方案」 |
| [03-你是AgentA.md](03-你是AgentA.md) | A 只写方案正文 | 「出一版升级方案。B 就一名」 |
| [04-你是AgentB.md](04-你是AgentB.md) | B 重读磁盘，只追加自己的稿 | 「你是 Agent B1，审核这份方案」 |
| [05-多名B各写各的.md](05-多名B各写各的.md) | 各写各的；读到别人的结论就停 | 「B1 和 B2 都审」 |
| [06-开始按方案执行.md](06-开始按方案执行.md) | 可以执行之后，你拍板，才由 A 改代码 | 「开始按方案执行」 |
| [07-记成升级需求.md](07-记成升级需求.md) | 技能做不到时落缺口稿，不改正文 | 「这是 skill 的问题，记成升级需求」 |

## 一份完整方案

| 文件 | 看什么 |
|---|---|
| [08-完整方案-登录与返参解密.md](08-完整方案-登录与返参解密.md) | 问题、改法、不改什么、验收，以及后面一轮轮审核原文。工程名是 `local-server`、`local-web`、`local-app`。这是历史长方案，现行的验收两节和一行一注释以技能正文为准 |

助手在你同意前不写方案。在你说出「开始按方案执行」前不改业务代码。
