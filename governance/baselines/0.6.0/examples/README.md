# 使用示例

看怎么开口、助手问什么、你怎么回、文件夹里会多出什么。

人名、仓库和问题是假的，问法是真的。01 到 07 贯穿同一件事：林夏的 `local-notes` 退出登录后，草稿还留在浏览器里。08 是另一份已经走完多轮审核的完整方案，路径和账号已换成 `local`。

```mermaid
flowchart LR
    A["说出问题"] --> B["同意出方案"]
    B --> C["A 写下 a-body.md"]
    C --> D["每名 B 另开对话，先提问再认可"]
    D --> E["已经出现的 B 都准许"]
    E --> F["你说开始按方案执行"]
```

建议先看 01。不先问人数看 02。方案正文看 03。提问轮和认可轮看 04。两名以上各写各章看 05。全票一次、未全票两次看 06。技能本身做不到看 07。要看一份长方案看 08。

## 开口

| 文件 | 看什么 | 你开口可以这样说 |
|---|---|---|
| [01-先问再出方案.md](01-先问再出方案.md) | 扫完要改代码，先问，不写方案 | 描述问题 |
| [02-人数由你指定.md](02-人数由你指定.md) | 没说人数也写方案，不预建 B 文件 | 「出一版升级方案」 |
| [03-你是AgentA.md](03-你是AgentA.md) | A 只写方案正文，写完不主动拉起 | 「出一版升级方案」 |
| [04-你是AgentB.md](04-你是AgentB.md) | 先提问，认可之后才能可以执行 | 「你是 Agent B1，审核这份方案」 |
| [05-多名B各写各的.md](05-多名B各写各的.md) | 各写各章；人要求派几名才派几名 | 自己另开两场对话 |
| [06-开始按方案执行.md](06-开始按方案执行.md) | 全票一次口令；未全票要下一条只有这八个字 | 「开始按方案执行」 |
| [07-记成升级需求.md](07-记成升级需求.md) | 技能做不到时落缺口稿，不改正文 | 「这是 skill 的问题，记成升级需求」 |

## 一份完整方案

| 文件 | 看什么 |
|---|---|
| [08-完整方案-登录与返参解密.md](08-完整方案-登录与返参解密.md) | 问题、改法、不改什么、验收，以及后面一轮轮审核原文。工程名是 `local-server`、`local-web`、`local-app`。这是历史长方案，现行的验收两节和一行一注释以技能正文为准。链路注释、逻辑变化时的日志、自审和每一轮审核里的安全评估、反问、覆盖五格，也以技能正文为准 |

助手在你同意前不写方案。在你说出「开始按方案执行」前不改业务代码。
