## 这版改了什么

人同意出方案之后就写固定十节。不必先指定审核人数，也不按人数预建审核文件。文首名单可以先空着。

每名 Agent B 使用人点的别名，或自加「B-」加八位十六进制。只在自己的大章节里追加。可以执行之前，先按自己读到的代码和方案里的问题独立推导并提问，再看做法和辩驳。Agent A 解释之后，该 B 认可，才能写可以执行。

已经出现的每一名 B 都准许时，人说一次「开始按方案执行」，才改代码。还没有全部准许时，这一次不改代码。人另起一条消息，正文只有这八个字，才可以直接执行。

人没有在当条消息里要求派出子代理时，Agent A 不主动拉起。人要求派出时可以派。用哪个模型，由人决定。

已经发出的方案：交给审核里没有「### 独立推导」的，仍按 0.5.2 判断，不补写提问轮。没有 `# Agent ` 章节的指定文件，仍看最后一节真实轮次。

## 使用者要做什么

- [x] 用新 zip 或新目录替换已安装的 Skill。不替换时，已安装的副本仍按旧规则先问人数
- [x] 无需迁移工作区（默认）
- [x] 其他：已经发出的业务方案不改写，也不补 `# Agent ` 章节

## 不兼容说明

新写出的方案使用提问轮和认可轮。旧方案不因缺少独立推导、提问或认可而无效。

五句触发不变。十节名称和顺序不变。动手仍要人说出「开始按方案执行」。全票之后不会自动改代码。
