# 升级双路径（A 出方案 / B 审核 / 人执行 / 效果核对）

本文件由开发仓在「写升级方案 / 你是 Agent A / 你是 Agent B / 审核 AP / 检查升级效果」时**整份加载**。分发包不含本文件。总流程仍以 `skill-governance.md` 为准。

口令权威在 `skill-governance.md` §14。不要另编一套。

## 1. 角色

| 角色 | 做 | 不做 |
|---|---|---|
| **A** | 确认工作区；扫描；写七章 AP 到 `governance/planning/upgrade-plan-v{版本}.md` | 不改技能正文；不建 CR |
| **B** | 独立实读文件；只在该 AP **文末追加** `## B{N} 审核结果` | 不改 A 正文；不执行 |
| **人** | 「同意执行」或「执行升级」才改技能 | — |
| **核对** | 人在同一会话要求核对时，由没有执行该版升级的另一个助手来做。执行者只回复「核对交给同一会话里的另一个助手。」，然后把第 7 节和 `governance/templates/upgrade-effect.md` 交给它 | 执行者不写清单，不发进度。核对者不把执行对话里的进度、工具说明、文件解说当证据。不改技能正文，不改方案正文，不建 CR；写盘只允许核对单本身；方案已删则把文首结论一行补进该版已有回归报告后删核对单。除此以外改文件算失败。不是 B 审核，不追加 `## B{N} 审核结果`，也不追加业务方案的 `## 第N轮` |

用户不必报目标版本。A 读根 `VERSION` 拟定。

## 2. Agent A

触发：升级这个 skill / 写一份升级方案 / 你是 Agent A / 先出方案再改。

1. **工作区确认**：展示根路径、`VERSION`、git HEAD（无 git 则写无）。等人确认后再扫描写盘。
2. 扫描 `SKILL.md`、`references/`、`VERSION`、`skill.json`、`governance/planning/`。若有 `outputs/skill-gaps/` 且 `status=draft` 的稿，必须读并在 AP-1 引用 `sg_id`。缺口稿不是执行许可。
3. 方案只能叫 `governance/planning/upgrade-plan-v{拟定版本}.md`。每周期一份。空模板 `governance/templates/upgrade-plan.md` 不许改来凑合。
4. 七章缺一 = 失败，不得请人同意。文首可加工作区快照与需求照抄，不得替代七章。
5. 每条结论带可信度标签：已验证 / 推断 / 参考（说明在方案模板文首）。推断只能写进 AP-5「推断待验证」，不得当事实写进 AP-2、AP-4。
6. 写完停止，同时给出两条路：

> 方案在 `governance/planning/upgrade-plan-vX.md`。
> - 直接做：回复「同意执行」或「执行升级」。
> - 先审核：新开对话说「你是 Agent B，审核 governance/planning/upgrade-plan-vX.md」。

## 3. 路径 H · 人直接执行

人说「同意执行」「执行升级」「按这个执行」。不要求已有 B 节。进入 `skill-governance.md` §2 从建 CR 起。CR 写：`执行授权: 人直接同意（未经 B）`。

## 4. 路径 B · 审核后再等人

触发：你是 Agent B / B1 / B2 / 审核这份升级方案 / 审核 upgrade-plan-vX.md。

1. 核对工作区与 A 快照同一仓、同一 `VERSION`/git；不一致则停止，不写审核节。
2. 独立实读 AP-4 列出的文件，禁止只读 AP。
3. 只在该 AP 文末追加 `## B{N} 审核结果`（未编号默认 B1）。禁止改 A 正文、其他 B 节。
4. 不得执行、不得建 CR、不得改 `SKILL.md`。
5. 审核节缺下列任一小节 = 失败：

| 小节 | 内容 |
|---|---|
| #0 | 工作空间核对 |
| #1 | 实读文件清单 |
| #2 | 七章是否齐全；AP-4 与实仓是否对得上 |
| #3 | 阻塞问题（无则写「无」）。#1～#3 每条发现带可信度标签：已验证 / 推断 / 参考 |
| #4 | 四档之一：通过-可执行 / 通过-待修订 / 修订-需再审 / 重做-需再审 |

只凭「推断」不能判阻塞：写成「请 A 把它放进 AP-5 推断待验证」。发现缺标签 = 该小节不全。A 把推断当事实写进 AP-2 / AP-4，B 应列为阻塞。

写完后告诉人：前两档可回复「同意执行」；后两档应让 A 修订——除非人明确覆盖。

## 5. 人覆盖 B

B 结语为「修订-需再审」或「重做-需再审」，人仍说「同意执行」：执行。CR 写 `执行授权: 人覆盖 B（B 结语=…）`。A/B 不得拦人。

## 6. 硬闸

1. 同一对话已经以 A 出过该 AP → 禁止转 B。请新开对话把路径交给 B。
2. 没有 AP 文件 → B 停止。
3. A 在人同意前改技能正文 = 失败。
4. B 改了 A 正文 = 失败，从 git 恢复 AP 后重审。
5. 发版后删除该 AP（含文末 B 节）。B 节已固化到 CR / CHANGELOG / 基线 / upgrade-to，不另存副本。

## 7. 效果核对

触发：检查升级效果 / 检查开发仓的实际升级效果 / agent A 已经升级完毕 / 升级做完了核对一下 / 对照方案看改完没有 / 审核一下升级结果 / 审核升级结果 / 已经升级完了。

这不是 B 审核。不追加 `## B{N} 审核结果`，也不追加业务方案的 `## 第N轮`。不顺手清残留。不改技能正文，不改方案正文，不建 CR；写盘只允许核对单本身；方案已删则把文首结论一行补进该版已有回归报告后删核对单。九节正文不另存。除此以外改文件算失败。

谁写：执行该版升级的助手不担任核对。收到核对口令，只回复「核对交给同一会话里的另一个助手。」，然后把本节和 `governance/templates/upgrade-effect.md` 交给同一会话里的另一个助手。执行者不写清单，不发进度。查完之前不向人发文字。禁止「继续检查」「逐项如下」「全部核对完毕」以及按文件名分段的解说。

核对助手不把执行对话里的进度、工具说明、文件解说当作证据。证据只打开对照清单点名的 CR、RR、CHANGELOG，以及这些记录里写出的路径。

1. 工作区必须是该技能开发仓。对本包说这些口令 → 停止，请人换到目标仓。不写核对单。
2. 对照清单，用到即停：
   - AP 还在：第 1 节抄 AP-1 的可验收编号。第 3 节抄 AP-5 的用例编号。第 6 节抄 AP-4 的文件。第 7 节抄 AP 里写明不改的事项。第 2、4、5、8、9 节打开证据再填。AP 文件在，但缺 AP-1 的可验收句或 AP-4 的文件清单：停止，写明缺哪一章。第 5、8、9 节仍按模板当场核对。
   - AP 已删：第 1 节只抄 CR 的「## 核对用预期」。第 3、4 节只抄 RR 的「## 核对用回归」「## 核对用结果」。第 6 节只抄 CR 的「## 核对用范围」。第 7 节只抄 CR 的「## 核对用不改」。不从 CHANGELOG 的散文里自行归纳出新编号。CHANGELOG 只用于第 5 节看版本标题。
   - 0.5.2 之前的版本没有这些新栏目：第 1 节改抄 Acceptance Criteria，第 3、4 节改抄 Test Results 和固定四问，第 6 节改抄 Scope 表，第 7 节改抄 Non-goals，按句拆开。RR 结论里点名没跑的，拆进第 4 节。来源写在该节最后一条：「来源是该版原有栏目，该版没有核对用新标题」。这不计入未解决，也不计入不改项被改。
   - CR 和 AP 都没有：停止。只回复「找不到对照清单」，写明缺方案还是缺 CR。不按目录印象编第 1、6、7 节。第 5、8、9 节仍然按模板当场核对。
3. 按 `governance/templates/upgrade-effect.md` 填。格式只在那份模板里。写到 `governance/planning/upgrade-effect-v{版本}.md`。对人回复只贴这份正文。
4. 文首计数与九节一致。未解决、未通过、版本不对齐、范围外改动、不改项被改、打包不符合、发布记录缺失，有一项不是 0，就写「不能发布」。这些都是 0，写「可以发布」。未跑单独计数，必须出现在第 4 节，不写成通过，也不因此改成不能发布。
5. 核对单不长期留在 `planning/`：
   - 方案还在：留给 `skill-governance.md` §2 第 11 步，与 AP 一起删。文首结论一行写入当版 RR。九节正文不另存。
   - 方案已删：把文首结论一行补进该版已有 RR，然后删除核对单。RR 不存在则留下核对单，回复里说明缺 RR，不另建 RR。

填写规则与模板注释同一套：

- 第 2 节和第 1 节序号对齐。每条只写「已解决」或「未解决」，下一行只写证据路径。
- 第 4 节和第 3 节序号对齐。每条只写「通过」「未通过」或「未跑」，再加一句结果。固定四问各占一条。RR 结论里点名没跑的，每条单独一行，写未跑。
- 第 5、8、9 节的条目固定，顺序不改，不增不删。每条只写「对齐 / 不对齐」「符合 / 不符合」或「在 / 缺失」，再加证据。
- 第 6 节一条文件一个编号。方案点名的写「已改」或「未改」。方案没点名却改了的，写「范围外」，证据写该路径。
- 第 7 节一条不改项一个编号。只写「仍在」或「被改了」，再加证据路径。
- 某一节没有条目时，该节只写「无」。
- 这九节以外的事项不写。不设「方案外」。
- 查完之前不向人发文字。禁止「继续检查」「逐项如下」「全部核对完毕」以及按文件名分段的解说。
- 对人回复只贴这份正文。界面自己折叠的工具记录不由本技能改写。
