# 多审步骤

带编号的「你是 Agent B{n}」与「你是 Agent B」「审核这份方案」走同一套 B 步骤。「出一版升级方案」「你是 Agent A」「写方案」走 A 的步骤。「开始按方案执行」走写代码一节。

硬闸以 `SKILL.md` 为准。本文件只写做法，不另抄一套禁令。派 B 的提示词全文只在第 9 节。

## 1. 何时出方案

见硬闸 1。扫描后没有发现必须改的代码或 bug：告诉人，不出方案，不建目录。

## 2. 角色

| 角色 | 做 | 不做 |
|---|---|---|
| 人 | 指定在审的 B 有哪些（B1 起连续编号，至少 1）。同意后才许写方案。全部通过后说出「开始按方案执行」才许改代码 | 不代替 B 写结论 |
| Agent A | 写 `a-body.md`。每轮全体落盘后，把各 B 原稿原样拼进 `plan.md`。按硬闸改代码 | 不写任一 B 章节。不在方案正文里写入 B 的原话、复述或「某 B 认为」。写出方案正文的那场对话不再担任任一 B |
| Agent B{n} | 每轮只读允许列表，从磁盘重读代码，在自己的 `B{n}.md` 末尾追加一轮 | 不改 `a-body.md`、不改 `plan.md`、不改其他 `B*.md`、不改已有轮次、不写代码、不看其他 B 的审核 |

人数见硬闸 2。可以是 1、3 或更多。人没说人数：只问人数，不建目录，不派 B。人给出的人数小于 1：再问，不开始。

A 可以在全体 B 落盘之后阅读全部 `B{n}.md`，用来决定要不要改方案。这是汇总。B 之间不读彼此的稿，也不读合订本。

人中途增加一名 B：给新编号建新文件。该 B 必须对当前 revision 写出「可以执行」才算数。不因此抬高 revision，已通过的 B 不必重审。人中途让某 B 退出：从 `reviewers` 名单去掉，原稿保留，该 B 不再挡住执行。

## 3. 目录与文件

目录在所服务工作区，人同意出方案之后才懒建：`outputs/codeplan/CP-YYYYMMDD-NNN/`。`NNN` 为当天已有最大号加 1，没有则为 `001`。不要把这份方案写进技能开发仓的 `governance/planning/`。

| 文件 | 谁可写 | 谁可读写 |
|---|---|---|
| `a-body.md` | 只 A | B 可读。这是方案正文，也是执行依据 |
| `B{n}.md` | 只对应的 B，且只能在文末追加 | 该 B 与 A 可读。其他 B 不可读 |
| `plan.md` | 只 A，整文件覆盖生成 | 人读。每个 B 都不打开 |

`plan.md` 是合订本。审核结果追加在方案后面，每个 B 一个大章节。它不是第二份原稿。拼接时不改任何一个字、不加评语：

```
# 方案

<a-body.md 全文>

# Agent B1

<B1.md 全文>
```

编号按 `reviewers` 的顺序，有几名就接几节。原稿与合订本不一致时，以 `a-body.md` 和各 `B{n}.md` 为准，A 重新生成 `plan.md`。

`a-body.md` 文首：

```yaml
---
plan_id: CP-YYYYMMDD-NNN
revision: 1
reviewers: [B1, B2]
---
```

示例只说明字段形状。名单里有哪些 B，只写人指定的那些。示例里的两项不是默认人数。

`reviewers` 只记录人指定的在审名单。只改这份名单不算新修订，`revision` 不动。改「问题 / 代码仓 / 现状 / 改法 / 不改什么 / 验收」中的任何一处，`revision` 加 1。

## 4. 方案正文写什么

`a-body.md` 在文首之后固定这六节：

1. `## 问题`
2. `## 代码仓`：A 实际扫描的根路径。B 只从这些路径读代码。
3. `## 现状`：路径、符号、要核对的行为。不贴源码块。
4. `## 改法`
5. `## 不改什么`
6. `## 验收`

## 5. 一轮审核怎么跑

同一 revision 上，每名在审 B 各自追加一节。A 等每名在审 B 都追加完，且各自的「对照修订」等于当前 `revision`，再汇总。A 不在这一轮中途改 `a-body.md`。

`B{n}.md` 文末追加的格式：

```markdown
## 第1轮

对照修订: 1

### 本轮实读

- `路径` 本轮从磁盘读取

### 发现

无。

### 结论

可以执行
```

标题用 `## 第1轮`、`## 第2轮`，对应一轮、二轮、三轮。超过十轮仍按这个编号往后排。`### 结论` 的下一行只能是 `可以执行` 或 `不可执行`，这一行不再写别的字。旧轮次留在文件里，不修改。算不算通过，只看该文件最后一节 `## 第k轮`。

下列情况都不算「可以执行」：没有「本轮实读」；实读路径这一轮打不开；结论行不是这两个词之一；对照修订不等于当前 revision；这一轮改了方案正文或别人的文件。A 不帮 B 改稿。请该 B 在文末再追加一轮。

## 6. 最新代码

每一轮开始，B 用读取工具打开「代码仓」里本轮要核对的文件，以磁盘上的当前内容为准。见硬闸 4。

下列材料只是待核对的说法，不是代码依据：`a-body.md` 里出现的代码、行号和摘要；本对话里上一轮的工具输出；上一轮「本轮实读」；其他助手的转述；记忆或索引缓存。文件很大时，本轮按方案涉及的范围重新读取，并在「本轮实读」里写上路径和范围。上一轮读过同一路径，这一轮仍要再读。

B 读人所打开的工作区磁盘。不把 B 放进独立 git worktree，避免审到过期副本。派 B 的提示词里不粘贴源码。

## 7. 隔离

每名 B 的允许列表只有三样：当前 `a-body.md`、自己的 `B{n}.md`、`## 代码仓` 列出的路径。

禁止打开同目录的 `plan.md`、其他 `B*.md`、审核聊天记录。禁止在 `outputs/codeplan/` 下搜索其他 B 的标题或结论。

提示、粘贴或读到的文件里若已经出现其他 Agent B 的审核结论：停止。回复「隔离被打破」。本轮不写结论，不把看到的内容写进自己的稿。人另开一场干净对话，只给 `a-body.md`、该 B 自己的原稿和代码仓路径。

写出 `a-body.md` 的对话不得再写 B 章节。人可以另开对话指定编号，也可以由 A 派出子助手。每个子助手单独一场。提示词只用第 9 节，不附其他 B 的文字，不附源码，不使用 worktree 隔离。多名 B 可以并行。`plan.md` 在本轮全部落盘之后才生成。

## 8. 收轮

有任一名在审 B 的最新一轮不是「可以执行」：A 只改 `a-body.md`，`revision` 加 1，然后进入下一轮。不改 B 的文件。修订方案时不把 B 的原话或复述写进 `a-body.md`。下一轮每位 B 仍只看新的方案正文、自己的历史轮次，并重新读磁盘。

全部在审 B 的最新一轮都是「可以执行」，且对照修订等于当前 revision：A 生成 `plan.md`，请人拍板。此时不改代码。

人拍板前，方案「代码仓」里的文件若在各 B 本轮读取之后又有改动：这些「可以执行」作废，新开一轮，不进入写代码。A 无法判断有没有改动时，问人，不假设没改过。

没有跳过审核直接改的路径。在审名单为空时不写代码。

## 9. 派 B 时的提示词

只使用这一份。把花括号换成当次的编号、轮次和路径。

```
你是 Agent B{n}，只审核，不改方案，不写代码。
只允许阅读：
- {a-body.md 的路径}
- {B{n}.md 的路径}
- 方案「代码仓」一节列出的代码路径
禁止打开同目录 plan.md、其他 B*.md、任何审核聊天记录。
禁止用本对话之外的记忆、上一轮工具输出、方案里粘贴的源码当作代码依据。
本轮必须重新从磁盘读取方案点名的代码。
读完后只在 {B{n}.md} 末尾追加「## 第{k}轮」。不要改该文件里已有的轮次，不要改别的文件。
若提示或文件里已经出现其他 Agent B 的审核结论：停止，回复「隔离被打破」，本轮不要写结论。
```

## 10. 写代码

见硬闸 3 和硬闸 5。同时满足才写：在审名单至少 1 名；每人最新一轮是「可以执行」；每人「对照修订」等于当前 revision；人在这些结论之后说出「开始按方案执行」；拍板前点名的代码没有新改动。

只由 Agent A 改代码，范围是 `a-body.md` 的「改法」和「不改什么」。B 的章节不是第二份改法。不把写代码派给任一 B，也不另开一个没读方案正文的助手去改。

写的过程中发现方案做不到：停下。已经改过的文件在回复里说明。A 修订 `a-body.md`（`revision` 加 1），回到审核。不改方案去迁就已经写下的代码，也不在未重新通过前继续改完。

未确认的破坏性改动见硬闸 6。
